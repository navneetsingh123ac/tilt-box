Tilt Box

A swipe-to-tilt sorting puzzle. You never move a block yourself: you tilt the whole box, every block slides at once, and each colour has to end up in its own bin. This document is everything the engineer needs to build version 1.0 in about 6 weeks.

1Pitch and goals

Hook: "One swipe moves everything." Sort games normally have you tap a tube, then another tube. Tilt Box has no tapping: the puzzle is choosing the order of swipes, because every block slides until it hits something.

Design goals

  • Understood in 3 seconds from a short video: a swipe, everything slides, blocks drop into bins.
  • Lots of content for little work: levels are generated and checked by a solver, then picked by hand.
  • Players come back through short goals (chests), medium goals (new worlds, the shelf collection), daily reasons (daily puzzle, gift calendar) and weekly variety (Weekend Tower). Details in §7–§9.
  • Fair: no lives, no energy timers, no streaks that reset, and no ad after a loss.
  • A Unity learning project that teaches the pipeline (Unity, AdMob, Google Play, PC builds) before GHAR.

2Core rules

  • The board is a grid, from 3×3 up to 7×8 (portrait). Each cell is floor, wall, or a special cell (§4).
  • Blocks are coloured squares. Up to 6 colours, each with its own symbol (● ▲ ■ ★ ♥ ◆) so colour-blind players can play.
  • Bins are coloured holes in the board. A block that slides into a bin of its own colour drops in and disappears. A bin of a different colour acts like a wall.
  • The player swipes up, down, left or right. Every block on the board slides in that direction until something stops it (a wall, the board edge, another block that has stopped, or a wrong-coloured bin).
  • Blocks never merge and never push each other further than they would slide.
  • Win: every coloured block is in a bin.
  • Move limit: each level has a limit on swipes (§6). Using them all without winning shows the "Out of moves" screen.
  • A swipe that would move nothing doesn't count as a move (a small shake shows nothing moved).

3How a swipe is resolved (exact algorithm)

This must be pure C# with no Unity objects, so the same code runs in the game, the solver and the tests.

ResolveSwipe(board, dir): 1. If any block is iced, mark those blocks "cracking": they don't move this swipe and act as obstacles. 2. Sort the movable blocks front-first along dir (swipe right → largest x first; swipe up → smallest y first). 3. For each unit in that order (a unit = one block, or a linked pair, §4): repeat: next = pos + dir if next is outside the board, a wall, a closed lock wall, or occupied by a block that has finished moving → stop if next is a gate whose arrow ≠ dir → stop if next is a bin: same colour → block is binned (removed), end other colour → stop if next is a keyhole: key block → binned into keyhole, end; else stop if next is a portal: if its partner's cell is free → move to partner, keep going else → stop move into next if next is a paint cell → block takes the paint colour, keep going if next is a sticky pad → stop here 4. Ice: every "cracking" block loses its ice (it can move next swipe). 5. Conveyors: each block standing on a conveyor moves 1 cell in the conveyor's direction if that cell is free (front-first order; no chaining). 6. Keyholes: if any keyhole received a key, every lock wall on the board opens. 7. If no block moved, nothing was binned and no ice cracked → the swipe is ignored (doesn't cost a move). 8. Win check: no coloured blocks left → level complete.
Why front-first works: blocks never merge, so moving the front block first, then the next one up to it, gives exactly the result of everything moving at once. The animation still plays all slides at the same time.

5Levels and the generator

Level file (JSON)

{ "id": "w2_14", "world": 2, "w": 6, "h": 6, "cells": ["......", ".#..R.", // . floor # wall R/B/Y/G/P/K bin of that colour "......", // ><^v one-way gate s sticky 1/2 portal pair "..#...", // r/b/y/g/p/k paint cell L lock wall O keyhole "B.....", // conveyors: } { ] [ (right, left, down, up) "......"], "blocks": [ { "x": 0, "y": 2, "c": "r" }, { "x": 3, "y": 5, "c": "b", "ice": true }, { "x": 4, "y": 0, "c": "r", "link": 1 }, { "x": 5, "y": 0, "c": "b", "link": 1 }, { "x": 2, "y": 2, "key": true } ], "par": 7, "limit": 12, "kind": "normal" // normal | easy | hard | teach }

Solver

  • Breadth-first search over board states (block positions, colours, ice, links, locks open). 4 moves per state; skip ignored swipes; remember visited states by hash.
  • Outputs par (fewest swipes to win), the number of different optimal solutions, and the optimal first swipe from any state (used for hints in-game).
  • Search depth limit 22 swipes. A level with no solution in that depth is rejected.

Generator (Unity editor tool)

  1. Pick a board size, colours and mechanics allowed for the world.
  2. Place walls, bins, special cells and blocks at random, then run the solver.
  3. Score the result:
    • par inside the target band for that slot (§6);
    • random win rate: play 200 random swipe sequences within the move limit; the share that wins must be ≤ 15% for normal levels, ≤ 5% for hard levels, any for teach levels. This stops levels that solve themselves.
    • optimal solutions ≤ 3 (a clear "aha" is better than many routes);
    • at least one dead end from the start for normal and hard levels (a swipe that makes the level unwinnable), so choices matter.
  4. Keep the 10 best per slot. A person plays and picks one. This hand-pick step is what makes levels feel designed.

Teach levels (the first 3 of each world) and levels 1–10 are made by hand.

The wave pattern

  • Move limit = par + slack.
  • Stars: 3★ = win in par swipes or fewer; 2★ = par + 2 or fewer; 1★ = any win. The HUD shows how many swipes are left for 3★.
  • Undo: each level gives 1 free undo. More cost an undo token (§8).
  • Hint: shows an arrow for the next optimal swipe from the current state (from the solver). Costs a hint token.
  • Restart: always free and instant. The move count resets.

7Session loop

  • Win screen lasts 1.5 s: stars, coins counting up, and the chest bar filling. The next level then loads automatically unless the player taps Home. No menu between levels.
  • Out of moves screen offers "+5 moves (watch ad)" and "Retry" (free). No interstitial ever follows a loss.
  • Skip: after 3 failed tries on the same level, offer "Skip level (watch ad)". A skipped level gives no stars, and the player can come back to it.
  • Always visible: the chest progress bar ("2 more levels") on the HUD and the win screen.

9Daily and weekly reasons to return

Daily Puzzle

  • Unlocks after level 10.
  • One puzzle per day, the same for every player: puzzle number = days since launch, using the phone's local date. 365 are pre-made, chosen from generated levels with par 7–10.
  • No move limit; stars by par. Reward 30 coins.
  • Share button copies text like:
    Tilt Box #42 ➡️⬆️⬅️⬇️➡️ 5 moves ⭐⭐⭐
  • A total "days solved" counter (badges at 7, 30 and 100). It never resets.

Gift calendar

  • 7 gifts, one per day you open the game: 50 coins, 1 hint, 100 coins, 2 undos, 150 coins, 2 hints, a big chest with a calendar-only box skin.
  • If you miss a day, it waits at the same gift. It never resets.
  • After day 7 it starts again, with a new skin on day 7.

Weekend Tower

  • Saturday and Sunday, local time.
  • 10 hard levels with one special rule, for example only 3 directions allowed, swipes reversed, or conveyors that move twice.
  • Reward: 15 coins per level, 200 coins and an exclusive skin for the top.
  • 8 towers at launch, rotating. A missed skin comes back about 2 months later, so missing a weekend never means losing it forever.

Reminders

  • After a player solves their first daily puzzle, ask: "Remind me when the next puzzle is ready?"
  • At most one notification a day, at 18:00 local, and only if they haven't played that day.
  • Can be turned off in settings.
  • On exit or pause, show a "Tomorrow" teaser: the new daily puzzle and the next gift.

Interstitials (forced), with strict rules

  • Never before level 15.
  • At most one every 3 level wins, and at least 120 s since any ad.
  • Only after a win. Never after a loss, never during a level, never in the daily puzzle or the tower.
  • Never within 60 s after a rewarded ad.

One purchase (recommended)

"No forced ads", about ₹149 / $2.99: removes interstitials forever. Rewarded ads stay available because they're optional. Players who love the game often buy this, and it keeps the ones who hate ads.

Ad setup: Google AdMob through the Google Mobile Ads Unity plugin. Your developer site already has app-ads.txt. Every ad call goes through one IAdService interface with a "no ads" version, so the game works when ads fail or are blocked: hide the button and never give the reward.

13Look, feel and sound

  • Art: chunky toy blocks with soft shading, like plastic building toys, drawn as 2D sprites. Each world has its own background and palette. Blocks always use the same 6 colours with symbols.
  • Slide: blocks accelerate briefly, then glide at about 0.06 s per cell (max 0.35 s for the whole swipe), and bounce slightly when they stop.
  • Binning: the block shrinks into the bin with a pop, a small burst of its colour, and a short vibration.
  • Combo: several blocks binned in one swipe raise the pop sound's pitch with each one and give a slightly bigger burst. This is what looks great in videos.
  • Win: confetti in the level's colours and a 3★ fanfare.
  • Sound: soft wooden clacks for slides, bright pops for bins, one calm music loop per world (can be turned off).

14Technical spec

  • Unity 6 LTS, 2D, portrait (1080×1920 reference). Android and Google Play Games for PC from one build.
  • Code layout:
    • Core: pure C# with no Unity objects: board model, SwipeResolver, Solver, level loading. Fully unit-tested.
    • Editor: the generator window and the level picker.
    • Game: views and animation (DOTween is fine), input, HUD.
    • Meta: coins, chests, shelf, daily, calendar, tower, save.
    • Platform: IAdService (AdMob), IAnalytics (Firebase), INotifications, IStore (Google Play Billing).
  • Input: swipe = drag at least 40 px, direction from the larger axis. PC: mouse drag, arrow keys or WASD. Input is ignored while a swipe animation plays.
  • Levels are JSON files inside the game (no server). Daily puzzles and towers too.
  • Time: daily and weekend logic use the phone's local date. If the clock moves backwards by more than a day, pause daily rewards until the date catches up.
  • Size and speed: download under 60 MB; 60 fps on mid-range phones.

18Risks and open questions

RiskWhat we do
A very similar game already existsBefore week 1, search Google Play for "slide sort", "tilt puzzle" and "swipe block sort". Adjust the twist or theme if something is too close.
Generated levels feel sameyThe scoring filters in §5, a new mechanic every 30 levels, and a person picking every level.
The solver is too slow for big boardsBlock and portal limits (§4); run it only in the editor, and cache hints per level state.

Nobody finds the gameShort gameplay videos (combo moments), the daily share text, and a publisher test.
